# 决策记录

## D-001：源码、Release、安装版和运行数据分开记账

**状态：已采用。** 同一个版本号可能同时存在源码 `main`、不可变 Release 标签/DMG、私有验证提交和旧的本机安装版。文档必须分别给出提交或版本，不能把“已提交”“已发布”“已安装”互相替代。

## D-002：保留仓库原生目录结构

**状态：已采用。** `assets`、`desktop`、`native`、`public`、`runtime`、`tests` 等目录按现有构建关系留在根目录，不为了项目模板移动到 `src`。Project Foundation 只增加治理和叙事文档，不重排业务源码。

## D-003：源码迁移只复制 Git 跟踪内容

**状态：已采用。** 迁移 `.git` 和 `git ls-files` 返回的路径，依赖、缓存和可再生成制品不复制。目标路径原有内容遇到冲突时先整体保存为同级恢复点，不覆盖或删除。

## D-004：知识库按阶段、按授权接入

**状态：已完成。** 源码迁移执行阶段明确不启动 OpenWiki、不接入 m-wiki；后续统一验收阶段才完成 m-wiki 注册和 OpenWiki 候选审阅/接受。历史记录保留当时边界，当前状态记录后续结果。m-wiki 仍只是浏览层，OpenWiki 仍遵循候选、审阅、接受流程。

## 既有稳定决策

- 控制 API、SSH 监听和反向代理目标只绑定本机回环地址；边界见 [SECURITY.md](../../SECURITY.md)。
- 公开发布、私有验证与当前安装状态分别记录；权威运行说明见 [PROJECT_STATUS.md](../PROJECT_STATUS.md)。

## D-005：完整快照单飞，并保留失败前的最后成功状态

**状态：源码候选已实现，等待构建与实机验收。** 主界面与菜单栏通过一次 catalog 读取组成 `bootstrap/state/docker` 原子快照；普通刷新合并，强刷在普通轮后升级执行。计算结果只有在失效 epoch 和 catalog revision 未变化时才能写缓存。刷新失败保留最后成功快照并标记 stale，所有会改变运行态的动作禁用；旧 `/api/bootstrap`、`/api/state` 和 `/api/docker` 保持兼容。

## D-006：SSH 四态动作与当前/历史错误分层

**状态：源码候选已实现，等待构建与实机验收。** 网页和菜单栏统一使用“已连接、已停止、连接中、连接失败”决定动作。域名入口终态失败但 SSH 仍健康时，只重检入口，不停止或重启 SSH。对外当前错误仅在最终失败时出现；历史错误保存在只读 `diagnostics`，不写入 catalog。
