# Local Ops 使用手册

[English](USER_GUIDE.md) · [项目说明](../README.zh-CN.md) · [安全说明](../SECURITY.md)

本文适用于 Local Ops v1.8.3 与 Apple Silicon macOS。

## 1. 安装、升级与打开方式

### 安装

1. 从 GitHub Releases 下载 `Local-Ops-1.8.3-arm64.dmg`。
2. 打开 DMG，把 **Local Ops** 拖到“应用程序”。
3. 从“应用程序”启动 App。

第一次启动时，Local Ops 会把当前用户的后台安装到 `~/.local/share/local-ops`，生成随机本机 API 密钥并注册 LaunchAgent。DMG 已经包含 Caddy、Process Compose 和原生钥匙串 Helper。

当前发布包使用 ad-hoc 签名而不是 Apple 公证。如果 Gatekeeper 阻止打开，请在“应用程序”中按住 Control 点击 App，选择“打开”并确认。

### 升级

退出 Local Ops，打开新版 DMG，并替换“应用程序”中的旧 App。下次启动会升级内置后台，同时保留 `catalog.json`、`last-session.json`、本机 API 密钥、钥匙串项目、日志和无端口访问授权。

当前替换内置后台会重启 Local Ops 控制面，也可能重启由 Process Compose Worker 托管的进程，包括 SSH 隧道。升级前应先结束正在进行的数据传输，升级后再确认所需服务和监听端口。

### 窗口与 App 的关系

- 关闭主窗口只会隐藏窗口，菜单栏快捷面板仍然可用。
- “退出 App”会先记录最新会话状态，再退出桌面界面。
- 本机控制面由 launchd 管理，因此已经运行的资源和反向代理可以独立于可见窗口继续工作。

## 2. 资源类型

- **托管服务**：Local Ops 通过 Process Compose 负责启动命令和进程生命周期。
- **SSH 隧道**：连接 SSH 主机，把本机回环端口转发到远端目标。
- **现有服务**：只探测可用性，不负责启动、停止或重复接管。
- **本地域名**：由 Caddy 把 `*.localhost` 域名（可带路径）转发到本机回环端口。
- **终端操作**：在 Terminal.app 或 iTerm2 中执行的命令、SSH 登录或 SSH 转发。
- **Docker 容器**：从本机 Docker Engine 读取的已有容器；Local Ops 不负责创建或删除。

## 3. 总览与“需要关注”

总览显示控制面持续运行时间、托管进程数量、现有服务可用性、本地域名和需要关注的资源数量。

点击“需要关注”会打开详细清单，每一项都会显示资源名称、原因、状态和跳转入口。数量可能包含：

- 已停止或健康检查异常的托管服务 / SSH 隧道；
- 离线或探测报错的现有服务；
- 需要手动处理的会话记忆资源。

## 4. 菜单栏快捷面板

点击 macOS 菜单栏中的 Local Ops 状态图标，会打开宽度 330 像素的紧凑面板，按以下顺序在第一层展示：

1. 服务
2. SSH 隧道
3. 终端操作
4. Docker 容器
5. 反向代理

服务、隧道、终端操作和容器使用对齐的末尾状态列：绿色表示开启或就绪，红色表示关闭，黄色表示正在处理。反向代理一半显示名称，一半靠右显示网页地址，不显示运行状态。

点击服务、隧道或容器会切换状态；点击终端操作会立即执行；点击反向代理会用默认浏览器打开。固定底栏包含刷新、显示控制台、浏览器打开、查看日志和退出 App。面板每 10 秒刷新一次，执行操作后会立即同步。

主控制台会同时刷新运行状态和最新资源目录。通过 Local Ops HTTP API、菜单栏进程或另一个已打开客户端新增、编辑资源后，无需重启 App 或重新打开窗口，页面就会自动同步。同步范围包括服务、SSH 隧道、现有服务、反向代理、终端操作和设置。

## 5. 托管服务

进入“服务 → 添加资源 → Node / 命令服务”。

| 字段 | 说明 |
| --- | --- |
| 显示名称 | 列表中给人看的名称 |
| 唯一 ID | Process Compose 和 CLI 使用的稳定小写标识 |
| 列表图标 | 卡片和表格中的品牌 / 工具图标 |
| 工作目录 | 项目的绝对路径 |
| 启动命令 | 通过用户登录 shell 执行的命令 |
| 说明 | 可选的资源说明 |
| 健康检查 URL | 可选的本机 HTTP 健康端点 |
| 分组 | 界面和进程命名空间 |
| 服务类型 | Node、普通命令或 Docker 命令服务 |
| 退出后重启 | 总是、仅失败时或不重启 |
| 本地域名 / 路径 | 可选，例如 `api.localhost/admin` |
| 服务端口 | 配置本地域名时必填 |
| 自动启动 | 服务调度器启动时自动运行 |

示例：

```text
显示名称：Order API
唯一 ID：order-api
工作目录：/Users/you/Projects/order-api
启动命令：npm run dev
健康检查：http://127.0.0.1:3000/health
本地域名：api.localhost
服务端口：3000
```

左侧主按钮用于开启或关闭。编辑、重启、日志和删除等操作放在“更多”菜单中；不支持某项操作的系统资源会直接隐藏对应按钮。拖动“排序”列手柄时，界面会先立即移动，再异步保存顺序。

服务配置了本机 HTTP 健康地址时，Local Ops 会把真实子进程与 Process Compose 的摘要状态分开监督，避免 Dashboard 实际仍存活却被误判为退出并重复启动。端口已由其他进程占用时会显示降级并阻止重复启动，不再无限重试；停止或重启会清理完整的托管进程树。没有健康地址的服务继续使用旧版本的直接生命周期。

## 6. SSH 隧道

下面的命令可以直接映射到表单：

```bash
ssh -NT \
  -o IdentitiesOnly=yes \
  -o ExitOnForwardFailure=yes \
  -o ConnectTimeout=5 \
  -o ConnectionAttempts=1 \
  -o ServerAliveInterval=30 \
  -o ServerAliveCountMax=3 \
  -i ~/.ssh/example_vps \
  -L 127.0.0.1:3000:127.0.0.1:3000 \
  deploy@203.0.113.10
```

填写 SSH 用户 `deploy`、SSH 主机 `203.0.113.10`、SSH 端口 `22`、本地端口 `3000`、远端主机 `127.0.0.1`、远端端口 `3000` 和私钥路径。上面的 IP 是文档专用示例地址，不是真实服务器。

卡片会把 SSH 跳板与转发路径分开显示：

```text
经由 deploy@203.0.113.10
本地监听 127.0.0.1:3000  →  转发目标 127.0.0.1:3000
```

Local Ops 会自动加入 `-NT`、`IdentitiesOnly`、`ExitOnForwardFailure`、`ConnectTimeout=5`、`ConnectionAttempts=1` 和断线保活参数，托管监听只绑定 `127.0.0.1`。连接失败或超时后 SSH 会退出，Process Compose 等待约 3 秒再启动下一次尝试，不会用几十秒的固定开机延迟。SSH 隧道表单不再提供“随服务调度器自动连接”：网页、菜单栏和批量按钮触发的手动连接最多重试 3 次；开启“启动 App 时恢复上次运行状态”后，开机恢复的隧道最多重试 40 次。

自动启动 SSH 前，Local Ops 会通过 `ssh -G` 读取最终生效的主机配置，所以 `frp-relay-01` 一类 SSH 别名会先解析成真实 `HostName/Port`。每轮连接先探测该端点：不可达时本轮快速退出，卡片保持“连接中”，并在“SSH 主机网络”详情中显示等待网络；Process Compose 约 3 秒后发起下一轮，端点恢复后立即进入 SSH 连接流程。

### 链路健康检查与状态

建议在隧道表单填写一个经过该隧道访问的本机 HTTP 地址，例如：

```text
http://127.0.0.1:18080/
```

本地端口开始监听只说明 SSH 转发存在，不代表远端 HTTP 应用已经就绪。Local Ops 现在把两种信号分开处理：

- **SSH/TCP 存活**：检查托管 SSH 进程和本地回环监听；只有这一层丢失才会触发 SSH 重启。
- **应用就绪**：可选地请求已配置的本机 HTTP 地址；HTTP `100–499` 表示就绪，`5xx`、连接失败或 10 秒超时表示降级。

应用就绪失败不会结束仍然存活的 SSH 进程，不会消耗 Process Compose 重试额度，并会持续探测直到应用恢复。

- **连接中**：包括等待网络、建立 SSH、自动重试和手动立即重试。此状态下主按钮不可点击，也不显示旧错误。
- **连接失败**：40 次开机恢复重试或 3 次手动重试已经用完但仍未通过检查；卡片底部显示具体错误，并提供黄色“立即重试”按钮。点击该按钮属于手动操作，会开始新的 3 次重试额度。
- **已连接**：SSH/TCP 隧道已经存活；可选 HTTP 应用检查降级时，“隧道健康检查”仍可单独显示“未就绪”。如果配置了对应域名入口，该入口也必须就绪，卡片才达到完全可用状态。
- **已停止**：隧道已停用，SSH 进程和本地监听均应消失。

隧道卡片只保留 SSH 主机网络、SSH 隧道、隧道健康检查和域名入口四项诊断。错误文案只在“连接失败”时出现在卡片底部；内容过长会滚动显示，悬停仍可查看全文。健康检查留空时会明确使用 TCP-only 存活判断，远端应用就绪状态保持未知。

如果“反向代理”中有域名的转发目标与隧道的本地监听端口相同，Local Ops 会自动把它识别为这条隧道的完整入口，并检查包含访问路径的实际 URL。入口检查接受 `2xx`、`3xx`、`401` 和 `403`。受认证保护的服务在登录前经常返回 `401 Unauthorized` 或 `403 Forbidden`；这只能证明请求已经到达应用，不代表用户认证成功。错误路径返回 `404`、服务返回 `5xx`、连接失败或 10 秒超时时会显示“域名入口：未就绪”，但不会重启已经健康的 SSH 隧道。页面分别展示：

- **SSH 隧道：已连接**：本机健康 URL 已经通过 SSH 转发收到有效响应。
- **域名入口：已就绪**：对应的完整 `.localhost` URL（包括安全入口路径）返回成功或重定向响应。

只有上面已配置的两层检查都成功，卡片右上角才显示“已连接”。未配置反向代理时，只要求 SSH 隧道健康检查成功。

完整入口直接来自现有反向代理配置，不会写死某个项目地址，也不需要在 SSH 隧道表单增加重复字段。

域名入口失败会使用当前 3 次或 40 次界面探测额度，但不会消耗 Process Compose 重启次数，也不会结束 SSH 进程。额度耗尽后会显示“连接失败”，但不再永久锁死：Local Ops 每 30 秒进行一次低频恢复探测。入口重新响应后，同一个健康的 SSH 进程会自动回到“已连接”。在这 30 秒内反复刷新页面只会复用已记录的结果，不会高频请求繁忙服务。

### 期望状态与停止审计

Local Ops 会把托管服务和隧道的期望状态，与 Process Compose 返回的瞬时进程快照分开保存。这样，即使捕获会话时刚好遇到编排器短暂重启，也不会把用户仍希望运行的资源从记忆会话中删除。启动、停止和重启会把来源、原因和时间写入：

```text
~/.local/share/local-ops/runtime/process-lifecycle.json
```

来源可区分网页 UI、API、菜单栏、App 启动、App 退出、健康逻辑和编排器观察。显式停止会把期望状态改为 stopped；瞬时观测到停止不会静默抹掉此前的 running 意图。

### 加密私钥与钥匙串

如果私钥设置了口令：

1. 在隧道表单填写私钥路径和口令。
2. Local Ops 先验证该口令能解锁这把私钥。
3. 原生 Security.framework Helper 把口令保存到 macOS 登录钥匙串。
4. 后台 SSH 通过受限 AskPass 只回答“私钥口令”提示。

真实口令不会进入 `catalog.json`、Process Compose YAML、命令参数、日志、API 响应或可迁移导出。配置仅保存随机不透明引用，而且 API 与导出也会移除该引用。

编辑时留空会保留钥匙串口令，输入新值会替换，勾选删除项会从钥匙串移除。项目缺失时 Local Ops 会明确报错，不会回退到明文存储、服务器账号密码、主机确认或键盘交互认证。

## 7. 现有服务与反向代理

“现有服务”只做监控。例如 `127.0.0.1:4173` 可以由其他 App 启动，Local Ops 仅探测健康状态，不会启动或停止该进程。

本地域名必须以 `.localhost` 结尾，目标必须为 `127.0.0.1:端口` 或 `localhost:端口`。域名后可以直接加路径：

```text
本地域名：panel.localhost/admin_abc
转发目标：127.0.0.1:18080
```

Caddy 仍按 `panel.localhost` 路由，快捷入口会保留 `/admin_abc`。

### 无端口访问

未启用时，链接会带 `:19080`。启用后，Local Ops 会安装 root 所有的 LaunchDaemon、Helper 和 PF anchor，把回环 80 端口转发到 Caddy。App 只在首次操作时请求管理员授权，不会监听局域网网卡。纯浏览器控制台无法发起这项系统授权。

## 8. Docker

Docker 页面通过本机 Docker CLI 和 Engine 读取容器。Engine 离线时点击“启动 Docker Desktop”，等待就绪后即可逐个启动、停止、重启容器，也可开启全部已停止容器。

Local Ops 不创建、不删除、不重命名、不导出容器，也不修改容器重启策略。配置导出永远不包含 Docker 资源。

开启会话恢复后，Local Ops 会记录稳定容器 ID 及 Compose 项目 / 服务信息。如果需要恢复容器，它会打开 Docker Desktop，最多等待两分钟，然后只启动被记住的容器。已经不存在的容器只会提示，不会重建。

## 9. 终端操作

选择 Terminal.app 或 iTerm2，可保存：

- 普通 shell 命令（可带工作目录）；
- 仅登录 SSH；
- SSH 本地转发。

SSH 终端操作使用和托管隧道相同的用户、主机、端口、私钥和可选转发字段，也能把加密私钥口令保存到钥匙串。未保存时，交互式终端仍可正常提示。第一次执行时，macOS 可能要求允许 Local Ops 在“系统设置 → 隐私与安全性 → 自动化”中控制所选终端。

## 10. 启动自动化与会话记忆

两个开关默认关闭，而且互相独立：

- **开机自启动**：登录 macOS 后只在菜单栏静默启动 Local Ops，不主动显示主窗口；需要时可从菜单栏打开控制台。
- **启动 App 时恢复上次运行状态**：只恢复上次记录时实际运行的自定义服务、SSH 隧道和 Docker 容器。

Local Ops 会定期记录状态，并在退出 App 时再记录一次。上次关闭的资源继续保持关闭；终端操作、反向代理链接、系统控制面进程和现有服务不参与恢复。资源已被删除时会跳过；部分恢复失败只写入桌面日志，不会阻塞其余 App 功能。

## 11. 配置导入与导出

导出包含：

- 自定义服务和 SSH 隧道；
- 现有服务监控；
- 反向代理；
- 终端操作；
- 界面语言和启动偏好。

不包含 Docker 资源、运行状态记忆、本机 API 密钥、私钥内容、私钥口令、钥匙串引用、系统端口或管理员授权。迁移到另一台 Mac 后，需要为加密私钥重新填写口令。

导入会替换上述资源集合，建议先导出备份。文件会在应用前完整校验，不相关的 JSON 会被拒绝。

## 12. 命令行

```bash
localops status                         # 查看 Core 和 Worker
localops open                           # 打开网页控制台
localops start                          # 启动控制面
localops stop                           # 停止控制面
localops restart                        # 重启控制面
localops logs                           # 查看 Core 日志
localops logs <进程ID> 300              # 查看进程最后 300 行
localops process start <进程ID>         # 启动自定义 Worker 进程
localops process stop <进程ID>
localops process restart <进程ID>
localops tui                             # Worker Process Compose TUI
localops tui-core                        # Core Process Compose TUI
```

## 13. 文件与日志位置

| 路径 | 用途 |
| --- | --- |
| `~/.local/share/local-ops/config/catalog.json` | 资源配置 |
| `~/.local/share/local-ops/config/last-session.json` | 上次会话记忆 |
| `~/.local/share/local-ops/config/process-compose.token` | 本机随机 API 密钥 |
| `~/.local/share/local-ops/generated/` | 生成的 Caddy / Process Compose 文件 |

单个进程可从“更多 → 日志”查看，菜单栏底部也可以直接打开日志目录。

## 14. 常见问题

- **服务一启动就停止**：查看日志，确认工作目录、可执行文件、PATH 和启动命令。
- **健康检查异常**：确认端点在本机监听，并返回小于 500 的 HTTP 状态码。
- **SSH 隧道失败**：查看卡片底部的连接错误；再在 Terminal 测试主机，确认私钥路径和权限、本地端口未占用、HTTP 健康地址经过该转发可访问。加密私钥还要确认页面显示钥匙串口令已保存。
- **钥匙串反复询问**：解锁 macOS 登录钥匙串并重新保存口令。Local Ops 不会把明文缓存到文件。
- **本地域名打不开**：检查 Caddy、转发目标和路径；URL 省略 `:19080` 时要确认无端口访问已启用。
- **无端口访问失败**：本机 80 端口可能被其他进程占用，停止对应监听后从 App 重试。
- **Docker 不可用**：安装或启动 Docker Desktop，等待 Engine 就绪。
- **终端操作失败**：确认 Terminal / iTerm2 已安装，并在“系统设置 → 隐私与安全性 → 自动化”允许 Local Ops。
- **界面未更新**：点击刷新，或进入“设置 → 重新加载全部配置”。
- **Dock 图标仍是旧版**：移除 Dock 中旧图标，从“应用程序”启动新版，等 macOS 更新 IconServices 后重新固定。

## 15. 卸载

1. 先在设置中关闭“无端口访问”，让 Local Ops 清理特权回环规则。
2. 退出 App。
3. 如果存在 CLI，执行 `localops stop` 停止控制面。
4. 从“应用程序”删除 **Local Ops.app**。
5. 如需连同配置和日志清除，删除 `~/.local/share/local-ops` 与 `~/Library/Logs/Local Ops`。

删除本机数据不可恢复，需要保留时请先导出配置。Local Ops 创建的钥匙串项目可以在“钥匙串访问”中搜索 `Local Ops SSH` 后删除。

## 16. 安全提醒

不要通过公网隧道暴露控制台，不要把 API 监听从 `127.0.0.1` 改到外网，不要提交真实 `catalog.json` 或日志，也不要把私钥复制进仓库。完整边界见 [SECURITY.md](../SECURITY.md)。
